# MAP001 - Lossy Mapping Transformation

## Description

The cross-family migration shim dropped information from the source
payload because the target shape has no slot for it.

## Category

Mapping Errors

## Severity

`warning`

## When emitted

Emitted by the UNTP ↔ CIRPASS shims in
[`compat/untp_0_7_to_cirpass_1_3.py`](https://github.com/artiso-ai/dppvalidator/blob/main/src/dppvalidator/compat/untp_0_7_to_cirpass_1_3.py)
and
[`compat/cirpass_1_3_to_untp_0_7.py`](https://github.com/artiso-ai/dppvalidator/blob/main/src/dppvalidator/compat/cirpass_1_3_to_untp_0_7.py).
Code constant: `MAP_CODE_LOSSY` in
[`compat/_mapping_codes.py`](https://github.com/artiso-ai/dppvalidator/blob/main/src/dppvalidator/compat/_mapping_codes.py).

## Common causes

- Multiple language entries on a UNTP `name` projecting onto a
  CIRPASS field that allows only one.
- UNTP-only fields (e.g. `traceabilityEvents`, durability extensions)
  with no CIRPASS reference-structure equivalent.
- CIRPASS-only fields dropped on the reverse projection.

## How to fix

`MAP001` is informational; no fix is required if you accept the
lossy projection. To suppress in CI, run the migration with
`--accept-warnings`. To preserve the dropped data, store the source
payload alongside the projected output (the shim is one-way).
